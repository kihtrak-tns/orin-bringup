## Read before P2 and later (not blockers for P1)
1. **The gate only works if Nav2 publishes to the raw topic.** If `path_gate.py`
   runs but the launcher is started *without* `LAKSA_NAV_CMD_TOPIC=/laksa/nav_cmd_vel_raw`,
   controller_server publishes straight to `/laksa/nav_cmd_vel` and bypasses the gate.
   Before any actuated goal, `ros2 topic info /laksa/nav_cmd_vel -v` must show exactly
   one publisher: `laksa_path_gate`. The reverse case fails closed: env var set but gate
   not running means no nav output reaches the supervisor.
2. **`path_gate.py` is not started by the launcher.** Run it by hand:
   `python3 $T/path_gate.py`. Its log goes to `~/laksa_run/latest/path_gate.log`, which
   exists only after `$L start|trial`; otherwise it logs to ROS only.
3. **The speed cap needs `LAKSA_NAV_ERPM`.** 0.22 m/s is about 911 eRPM (620 eRPM = 0.1497 m/s).
   Without the override, the yaml's `navigation_max_erpm: 620` caps navigation at 0.15 m/s.
4. **Each plan is checked once, when it arrives**, against the latest costmap. It isn't
   re-checked as the costmap changes. RPP collision detection and the supervisor still own
   in-motion safety. A console PLAN request during an active goal also publishes `/plan`,
   and the gate would evaluate it too: a FAIL latches (safe); a PASS could only precede the
   goal's own plan check.
5. **Console:** closing *any* console tab zeroes the heartbeat, as it did before. With the
   fix, another tab that's mid-hold now has to release and press again. That's the safe direction.
6. **Pre-existing, not changed:** `console_node.py` logs the full console URL *with the token*
   at WARN on startup, so `~/laksa_sessions/*/console.log` contains it. Never copy those logs
   into results.
7. **No rebuild needed.** `~/laksa_ws/src` symlinks into this checkout, and Python resolves
   `laksa_learned_driver.hold_latch` from `laksa_ws/build` (symlink-install). The console
   change goes live on the next console start.
