## Verdict
**PASS (6/6).** The "Done when" condition is met: the DriveCommand values
were echoed end-to-end in VehicleState, and the brake field produced a real
False→True transition. The only change from re-run 2 is holding
`/laksa/brake=false`, so this is live confirmation of the root cause in the
findings addendum (the brake latch that is on at boot). Hypotheses (a) and (b)
stay ruled out: the decode is correct, and no output is inhibited by the VESC
being unpowered.

What this does and doesn't prove:

| observation | proves |
|---|---|
| steering 0.1 → `steering_target_rad` 0.0981, servo cmd 100° → 94° (1611 → 1544 µs) | `steering_angle_rad` is decoded correctly and drives the PCA9685 command |
| brake=False → `brake_active` False; brake=True → True (with the latch released) | the `brake` field is decoded correctly |
| brake=True → steering target 0.0 and servo back to 100° | `apply_drive_command` centres on brake, as the addendum says |
| `requested_erpm` 0 throughout | speed 0 decodes to 0 only; the speed/ERPM scale factor is still unmeasured, as intended |
| `command_fresh` True while publishing, False within 1 s of silence | the command freshness timeout works |

## Caveats and follow-ups (none of them block this verdict)

1. **Rounding in the echoed angle.** 0.0981 rad against 0.1000 commanded, and
   6° off-centre against 5.73° commanded. The target seems to follow
   whole-degree servo quantisation or clamping in the firmware. It's within
   tolerance, but Phase B should expect whole-degree steering resolution.
2. **Steering direction, not yet observed physically.** +0.1 rad (left, per
   REP-103) mapped to 94°, below the 100° centre. Whether 94° is physically
   left is a Phase B observation.
3. **Did the servo physically move?** Unknown. The firmware commanded 94° with
   the main battery unplugged. Whether the servo has power without the main
   pack is still an open continuity item. See *Human confirmation needed*.
4. **The timeout step shows less than its label says.** `brake_active` was
   already True from the brake step, and the servo sample at +0.05 s predates
   the 500 ms timeout. The step only shows `command_fresh` dropping. It does
   not show that the timeout itself centres the steering or engages the
   brake. That still belongs to Phase C's stop-method test, which should start
   the silence from an unbraked, off-centre state.
5. **The latch comes back after every session reset.** The agent logged
   session resets at 04:06:14Z, 04:07:04Z and 04:12:25Z. The run passed with
   the continuous republish, but without the run's start time I can't tell
   whether a reset landed inside a publishing step. Any future command
   publisher, including `laksa_teleop_supervisor`, must re-release
   `/laksa/brake` continuously or on every reconnect, not once. The session
   churn in `notes/microros_link_stability.md` is still open and still blocks
   Phase C.
