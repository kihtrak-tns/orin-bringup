## Notes

- **The first post-reboot sample showed link ERROR** ("one or more topics
  stale/missing") at 04:55:26Z, ~56 s after the session was established.
  21 s later it was OK, and no session reset was logged in between. This is
  likely a startup transient in laksa_health's staleness window (samples
  aged before the first state messages arrived). It is not an A3 failure,
  but worth checking if it recurs on later boots.
- **laksa_health will show periodic ERROR/stale diagnostics whenever the
  still-open micro-ROS session churn happens**
  (`notes/microros_link_stability.md`). That is expected and not an A3
  failure. A3 is about boot-time automation, not that separately tracked
  instability. Not addressed here.
- **VESC WARN is expected** while the battery is unplugged (no telemetry),
  although the message text says "nominal" at WARN level. That's a wording
  mismatch in laksa_health, not investigated.
- **Cosmetic bug:** laksa_health's console log prints `laksa_health: ?`
  every second (the summary level name doesn't resolve). It fills the
  journal at 1 line/s. Not fixed.
- The latch interplay from A1b doesn't affect this task: nothing publishes
  `/laksa/brake`, so the firmware stays braked and centred at boot, which is
  the safe default.
