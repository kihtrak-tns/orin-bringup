## 2. Launch file and parameters

The launch directory (listed, not guessed) has `sllidar_a2m12_launch .py`.
Upstream, the filename contains a **stray space before `.py`**. It is
invoked with the name quoted exactly. Defaults in that file: port
`/dev/ttyUSB0`, baud 256000, `frame_id=laser`, `angle_compensate=true`,
`scan_mode=Sensitivity`. The node's own built-in baud default is 1000000.

Invocation used, overriding port and baud explicitly:
```
ros2 launch sllidar_ros2 "sllidar_a2m12_launch .py" serial_port:=/dev/laksa_lidar serial_baudrate:=256000
```
`/dev/laksa_lidar -> ttyUSB0` (udev rule untouched).

Upstream quirk: this launch file declares `scan_mode` but never passes it to
the node. The driver picked **Sensitivity** anyway as the device default,
so the effect was the same.

## Why 12.8 Hz and not 10 Hz

In this driver commit, `scan_frequency` (default 10) is only used to size
the angle-compensation buffer and in the log line. The motor is started
with `setMotorSpeed()` with no argument, i.e. the device's default speed.
On this unit (firmware 1.32, hw rev 6) that default is ~12.8 Hz. So the
"scan frequency:10.0 Hz" log line is nominal, not the actual rate. The rate
is very stable (std dev ~2.5 ms), so this is not a fault.
