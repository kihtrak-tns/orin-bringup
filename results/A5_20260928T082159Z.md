## Caveats / notes for later
- **Image/depth ≈ 12–17 Hz while the grab is configured at 60 fps.** That
  is plausible for NEURAL_LIGHT on an Orin Nano at HD720, and
  `ros2 topic hz` (Python) itself tends to under-read 1280×720 image
  streams. Not a defect for A5, but anything that assumes 30+ Hz depth
  (Phase D/E) should measure with a C++ subscriber or rosbag timing, and
  tune `grab_frame_rate` / `pub_frame_rate` / resolution / depth mode.
- **TF:** the wrapper publishes `odom → camera_link` and `map → odom`
  while running (defaults `publish_tf` / `publish_map_tf` = true). Only
  while it's up, but relevant when integrating with the LiDAR `laser` frame
  and any future odometry source (only one node may own `odom → base`).
- **`zed_msgs` 5.3.0** (apt) against wrapper 5.5.0: the v5.5-only fields
  (`pose_confidence`, `duplicated_image`) are absent. The node runs fine.
- **Installer side effects** (checkpoint 2): systemd/udev upgraded
  3.17 → 3.22 and the initramfs regenerated. **Not yet exercised by a
  reboot.** Worth one reboot check that A3's boot services still come up
  (`NRestarts=0`, `/diagnostics` fresh) before relying on them.
- **Observed, not investigated:** `/laksa/imu/data` read ~28 Hz during this
  run (it was caught by the topic filter), against ~41 Hz in the firmware
  findings. The Orin was heavily loaded (neural depth + tracking), so this
  may be Orin-side, but it is worth re-measuring unloaded as part of the
  open micro-ROS link work.
- Not done (out of scope): boot integration, URDF/extrinsics for the
  ZED on the car, NEURAL/NEURAL_PLUS optimization, the Python API.
